# د ښوونکو مسلکي پراختيا مديريت (PWA)

د تعليمي ادارې د ښوونځي، ښوونکو، مشاهده، پلانونو او راپورونو د مديريت سيستم — **آنلاین او آفلاین** دواړه حالتونو کې کار کوي. د Android په موبايل کې يې د عادي اپلیکېشن په څېر نصب کیدی شي (PWA).

---

## ۱) د Supabase ډيټابیس جوړول (لومړی ګام)

1. [supabase.com](https://supabase.com) ته ولاړ شئ او **New project** کېکاږئ (خپله سیمه/پټنوم وټاکئ).
2. **SQL Editor** خلاص کړئ، `schema.sql` دایره باندې یې ولیکئ او **RUN** کېکاږئ (یو ځل بس).
3. **Settings → API** ته ولاړ شئ او دا دوه ارزښتونه کاپي کړئ:
   - `Project URL`
   - `anon public key`
4. په دې ډاکنه کې `config.js` خلاص کړئ او همدې دوه ارزښتونه يې ولیکئ:

```js
window.APP_CONFIG = {
  supabaseUrl: 'https://xxxx.supabase.co',
  supabaseAnonKey: 'eyJ...',
  maxAccountsPerDistrict: 8
};
```

> که دا دوه خالي پاتې شي، اپلیکېشن په **محلي حالت** (local mode) کې کار کوي — ټول معلومات په خپل موبايل/کمپیوټر کې خوندي کېږي.

---

## ۲) Github ته اپلوږل

1. خپل Github اکاونټ کې **New repository** جوړ کړئ (خالي وي، README به يې نه جوړوئ).
2. د دې ډاکنې ټول فایلونه (index.html, js/, css/, lib/, icons/, manifest.json, sw.js, config.js, schema.sql, first-admin.sql, netlify.toml) کاپي کړئ او په **Add file → Upload files** کې يې اپلوږئ.
3. **Commit changes** کېکاږئ.

## ۳) Netlify باندې deploy

1. [netlify.com](https://netlify.com) ته ولاړ شئ او **Add new site → Import an existing project from Git** کېکاږئ.
2. خپل Github repository وټاکئ.
3. نور تاسو ته هېڅ ګام پاتې نه دی — `netlify.toml` په اتومات ډول کار کوي.
4. **Deploy site** کېکاږئ.

اپلیکېشن اوس په دې نښه کار کوي: `https://<خپله-آدرس>.netlify.app`

## ۴) لومړی کارونه

| ګام | څوک | څه |
|---|---|---|
| ۱ | **مالک (Supabase)** | `first-admin.sql` اسکرېپټ په **SQL Editor** کې RUN کوي — مخکې یې په وروستیو ګام کې خپل **برېښنالیک، پټنوم، نوم، ولایت او ولسوالۍ** لیکي. اسکرېپټ ولایت + ولسوالۍ ثبتوي او **عمومي مدیر** حساب جوړوي |
| ۲ | **عمومي مدیر** | اپلیکېشن کې ننوتل کوي → خپل ډشبورډ ته ځي (د عمومي مدیر ډشبورډ) → نور ولایتونه او ولسوالۍ ثبت کوي، د هرې ولسوالۍ د اعتبار نیټه او محدودیتونه ټاکي، او د ثبت شویو عایدونو لیکل کوي |
| ۳ | نور غړي | خپل حسابونه جوړ کړي → ولایت/ولسوالۍ **یوازې له عمومي مدیر په لور ثبت شویو لیستونو څخه ټاکي** (لیکل نشي، انتخاب دی) (هره ولسوالۍ تر **٨** حسابونو پورې) |

> **یادونه:** کله چې هیڅ ولایت/ولسوالۍ ثبت شوي نه وي، د ثبت پر پاڼه «اوس مهال په سیسټم کې هیڅ ولایت ثبت نه دی» ښکاري — لومړی ګام ۱ ترسره کړئ.
>
> که وروسته بل څوک هم عمومي مدیر وټاکل شي (Supabase SQL Editor):
>
> ```sql
> UPDATE public.profiles SET role='super'
> WHERE email = 'new@example.com';
> ```

## ۵) عمومي مدیر ډشبورډ

- عمومي مدیر یو **جلا ډشبورډ** لري چې نور څوک يې نه ګورې:
  - **ولایتونه** — ثبت او لړلیک
  - **ولسوالۍ** — د ولایت لاندې ثبت، د اکاونټونو شمېر (`x / 8`)، **د اعتبار نیټه** او **محدودیتونه** (هر وخت يې بدلولي سئ)
  - **عاید** — د هرې ولسوالۍ لپاره د ثبت شوی پیسې (مبلغ + هجري نېټه + یادښت)
- یوې ولسوالۍ معلومات یوازې هغې ولسوالۍ خلک يې ګوري — بلې ولسوالۍ ته نه ښکاري (د ډيټابیس په واسطه ټینګ).
- هر جوړ شوی اکاونټ **اتومات** د خپلې ولسوالۍ «علمي غړي» لړلیک ته اضافه کېږي.

## ۶) د اکاونټ برخه

- په پورته سرپاڼه (header) کې د اکاونټ برخه **هر وخت** ښکاري: نوم، سمت (عمومي مدیر/علمي غړی) او د وتلو تڼۍ؛ که ننوتلی نه وي، د «ننوتل» تڼۍ.
- په **تنظیمات** کې هم اکاونټ یوه **جلا برخه** ده: ستاسو معلومات (نوم، برېښنالیک، تلیفون، سمت، ولایت — ولسوالۍ، د اعتبار نیټه، محدودیتونه) او **د خپلې ولسوالۍ اکاونټونو لړلیک** (`x / 8`).

## ۷) د موبايل باندې نصب (PWA)

- په **Chrome (Android)** کې: مېنو ☰ → **Add to Home screen / ښوونه پورته کول** → اپلیکېشن د ټيليفون په سکرین کې د عادي اپلیکېشن په څېر راځي.
- اپلیکېشن **آفلاین** هم کار کوي — معلومات په موبايل کې خوندي کېږي، او هغه مهال چې اړیکه راوپورته شي، په اتومات ډول د Supabase ډيټابیس سره همغږيږي.

## ۸) د حسابونو محدودیت

- هره ولسوالۍ: تر **۸** حسابونو پورې — دا حد په ډيټابیس کې هم ټینګ دی (یوازې په UI کې نه دی).
- د حسابونو شمېر په عمومي مدیر ډشبورډ کې ښکاره کېږي (د بېلګې په څېر `۳ / ۸`).

---

## تېکنیکي لنډه

| برخه | تفصيل |
|---|---|
| ډيټابیس | Supabase (Postgres) — `provinces`, `districts` (اعتبار + محدودیتونه), `profiles`, `revenue` (عاید), `records` + RLS |
| آفلاین | IndexedDB + outbox (د هر بدلون لپاره) |
| همغږي | اتومات: د اړیکې د راوپورته کېدو پر مهال + هرې ۲ دقیقو وروسته؛ معياري اصول: وروستۍ لیکلې پاڵیتل کېږي (last-write-wins) |
| نېټې | هجري شمسي (Jalali) — ټول ځایونه |
| ژبې | پښتو + دري |
| PWA | manifest + service worker (آفلاین shell) |

## ۸) نوې بدلونونه (v3)

- **`schema.sql` بیا چلوئ:** د `complete_registration` پارامترونو ترتیب سم شو (پخوا په SQL Editor کې تېروتنه ورکوله). د ۸ اکاونټونو حد اوس په سرور کې ټینګ دی، نه په اپلیکېشن کې. که مخکې schema چلولې وي، همدا فایل بیا RUN کړئ (خوندي دی).
- **Sync:** د ولسوالۍ د ورکېدو پر مهال outbox نه پاکېږي؛ د pull پر مهال ثبت شوي بدلونونه نه ضایع کېږي؛ آفلاین بیا پرانیستل کار کوي.
- **ګډ موبايل:** که بله ولسوالۍ په همدې موبايل کې ننوځي، د پخوانۍ ولسوالۍ محلي معلومات پاکېږي.
- **موبايل:** لاندې ناوبري، د جدولونو کارت بڼه، د لټون آیکن، safe-area، `dvh`.
- **`sw.js`:** د اپ کوډ network-first دی، نو نوې نسخه سمدستي رسېږي. هر ځل خپرونه کې `VERSION` لوړ کړئ.

- **نېټې (v4):** ټولې نېټې هجري شمسي دي او په لاس لیکل کېږي (`۱۴۰۵/۰۷/۲۶`)؛ میلادي نېټه هیڅ ځای نه ښکاري. دننه په ISO (میلادي) ذخیره کېږي ترڅو sync او ترتیب نه شي خراب.

## ۹) د v6 لپاره Supabase ګامونه
۱. `schema.sql` بیا په SQL Editor کې RUN کړئ (خوندي دی، موجود معلومات نه ړنګوي).
۲. `first-admin.sql` یوازې لومړي ځل RUN کړئ (خپل برېښنالیک/پټنوم دلته ولیکئ).
۳. د سوپر ایډمین حساب په Supabase کې `role='super'` لري؛ هېڅوک بل په اپلیکېشن کې نشي جوړېدای.
۴. `config.js` کې Supabase URL او anon key ولیکئ — که خالي وي اپلیکېشن بې اکاونټ (local mode) کار کوي.
